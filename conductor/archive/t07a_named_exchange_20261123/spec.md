# T07a — scope and acceptance

Atlas must consume the actual output of the existing limma numerical core through a named, versioned file boundary. Select the smallest supported synthetic contract, preserve the existing independent R reference and give each repository a single clear owner.

## Inputs

- Reviewed limma named consumer/exporter and canonical `docs/named-consumer-v1.md`.
- A real published immutable producer commit after local strict verification and an actual hook-checked commit.
- Unchanged public synthetic `complete` and `missing` R fixtures and their prespecified field-specific tolerances.
- Existing atlas Python development tooling, Rust toolchain and central policy/privacy scanner.

## Bounded outputs

- A committed immutable producer pin.
- A standard-library receiver that invokes the actual exporter, validates schema/identities/method/scale and compares every numerical field and nonfinite result with the independent reference.
- A mandatory strict verification gate and source-bound receiving receipt.
- Rejection regressions for source drift, malformed/ambiguous metadata, shape/order/uncertainty/missingness corruption, failed commands and output/input aliasing.
- Documented producer-first integration order, native hooks and separate scientific/device gates.

## Exit criteria

The actual file exchange, the combined strict local checks and independent peer review must pass at the recorded source/content identities. Document any failed attempts and retain the original tolerances. Archive only this bounded exchange once those criteria pass; hosted candidate checks and final local commit-hook enforcement remain required before integration.

No new numerical algorithms, core runtime dependencies, production data parser, preprocessing method, source admission, owner-device acceptance or clinical inference is included. A scale declaration is transported, not scientifically established by the receiver.

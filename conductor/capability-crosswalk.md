## Execution rule (Ponytail full)

At the start of each ready batch, name its actual scientific consumer and any concrete upcoming consumer in the other stream, then choose reuse / small extension / existing external tool / defer. If both need the same semantics, qualify the smallest common capability once at its existing owner immediately before the first consuming task. If the second use is only hypothetical, keep the first implementation narrow and reusable at its existing boundary; do not introduce a shared library, service, extra project or dependency for a speculative consumer. Record the selected decision and exact receiving evidence in the owning existing plan/PR; do not copy status here.

- Preserve both streams' current prerequisites, including N0/N1, source rights, applicable institutional and actual-device gates. A completed shared technical contract is not clinical inference or scientific admission. No blanket prerequisites across streams.
- Existing T01/T07/T02 scientific work continues in its established order. V01.01 source retrieval and literature metadata can proceed in parallel when paths and source rules permit. V01.02/03 must await actual event data and appropriate permissions; a missing source is a hold, not a reason to build infrastructure.
- Reuse current strict verification, exact-current-base native-hook replay, privacy, dependency and provider checks. Review and merge one bounded increment when accepted; preserve failure receipts and verify receiving main; prune only observed merged heads. Update the owning track and GitHub issue; archive only the completed increment. Do not edit or merge competing drafts without their owner and acceptance.
- Do not add capabilities just to fill this crosswalk. If an extension has no consumer, delete/defer it; if two consumers' scientific semantics differ, share only source/IO/assurance, not the method or admission decision.
